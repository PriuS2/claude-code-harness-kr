# CI Analyze Failures

CI/CD 파이프라인의 실패를 분석하여 원인을 특정하는 스킬.
GitHub Actions, GitLab CI 등의 로그를 해석합니다.

---

## 입력

- **CI 로그**: 실패한 잡의 로그
- **run_id**: CI 실행의 식별자 (있다면)
- **저장소 컨텍스트**: CI 설정 파일

---

## 출력

- **실패 원인 특정**: 구체적인 원인
- **수정 제안**: 대응 방법의 제안

---

## 실행 절차

### Step 1: CI 상태 확인

```bash
# GitHub Actions 의 경우
gh run list --limit 5

# 최신 실패 확인
gh run view --log-failed
```

### Step 2: 실패 로그 취득

```bash
# 특정 run 의 로그
gh run view {{run_id}} --log

# 실패 스텝만
gh run view {{run_id}} --log-failed
```

### Step 3: 에러 패턴의 분석

#### 빌드 에러

```
패턴: "error TS\d+:" 또는 "Build failed"
원인 후보:
- TypeScript 형 에러
- 의존성의 부족
- 문법 에러
```

#### 테스트 에러

```
패턴: "FAIL" 또는 "✕" 또는 "AssertionError"
원인 후보:
- 테스트의 실패
- 테스트 타임아웃
- 모의의 불일치
```

#### 의존성 에러

```
패턴: "npm ERR!" 또는 "Could not resolve"
원인 후보:
- package.json 의 불整合
- 비공개 패키지의 인증
- 버전 경쟁
```

#### 환경 에러

```
패턴: "not found" 또는 "undefined"
원인 후보:
- 환경 변수의 미설정
- 시크릿의 부족
- 경로 문제
```

## 에러 패턴 사전

### TypeScript 에러

| 에러 코드 | 의미 | 일반적인 수정 |
|-------------|------|-------------|
| TS2304 | 이름을 찾을 수 없음 | import 추가 |
| TS2322 | 형이 일치하지 않음 | 형 수정 |
| TS2345 | 인수의 형이 다름 | 인자 수정 |
| TS7006 | 암묵적 any | 형 주석 추가 |

### npm 에러

| 에러 | 의미 | 일반적인 수정 |
|--------|------|-------------|
| ERESOLVE | 의존성 해결 실패 | package-lock 삭제 & 재설치 |
| ENOENT | 파일을 찾을 수 없음 | 경로 확인 |
| EACCES | 권한 에러 | CI 설정 확인 |

### Jest/Vitest 에러

| 에러 | 의미 | 일반적인 수정 |
|--------|------|-------------|
| Timeout | 테스트 타임아웃 | 타임아웃 연장 or 비동기 수정 |
| Snapshot | 스냅샷 불일치 | `npm test -- -u` |

---

## 복수 에러의 우선순위

1. **빌드 에러**: 최우선으로 수정
2. **의존성 에러**: 빌드 전에 해결 필요
3. **테스트 에러**: 빌드 성공 후 대응
4. **Lint 에러**: 마지막으로 대응
